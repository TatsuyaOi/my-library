2. 基礎理論・数学

2進数・ビット演算
ビット（bit）：0か1のどちらかを表す情報の最小単位。8bit = 1byte。
2進数 → 10進数：各桁を2の累乗として足します。例：10110₂ = 16 + 4 + 2 = 22₁₀。
10進数 → 2進数：2で割った余りを下から読む方法、または「どの2の累乗を足すか」で考えます。
演算1になる条件典型用途
AND両方1必要なビットだけ取り出す（マスク）
ORどちらか1特定ビットを1にする
XOR異なる反転・差分・パリティ
NOT0↔1全ビット反転

ビットマスクは「見る場所だけ1にした値」。対象値とANDを取ると必要部分だけ残せます。

ひっかけ： XORは「どちらか一方だけ1」。ORの「少なくとも一方が1」と混同しない。
集合・ベン図

和集合 A∪BはAまたはBに属するもの。積集合 A∩BはAとBの両方。補集合は全体集合のうちAでない部分です。

試験ではベン図だけでなく、データベース検索条件や論理式との対応も狙われます。ANDは積集合、ORは和集合の感覚です。

グラフ・DFS・隣接行列

グラフは頂点（vertex）と辺（edge）で関係を表すデータ構造です。隣接行列では、頂点iとjが接続していれば該当セルを1などで表します。

DFS（Depth-First Search、深さ優先探索）は、一方向へ行けるところまで進み、行き止まりで戻る探索です。実装では再帰またはスタックが自然です。一方、BFS（幅優先探索）はキューを使うのが典型です。

ユークリッドの互除法

最大公約数を求める方法。gcd(a,b) = gcd(b, a mod b)を、余りが0になるまで繰り返します。

gcd(48,18)
48 mod 18 = 12
18 mod 12 = 6
12 mod 6  = 0
→ 最大公約数 6

科目Bでは再帰関数として出ることもあります。

3. アルゴリズム・プログラミング・データ構造

科目Bの中心。 「何をしているコードか」より先に、変数・添字・データ構造がどう変化するかを追うのがコツです。
擬似言語の読み方：変数・代入・分岐・ループ

代入は右辺を計算して左辺へ保存する操作。数学の等式とは違います。x ← x + 1は「現在のxに1加えた値でxを更新」です。

条件分岐は条件の真偽で処理を分けます。複合条件ではAND/ORと括弧の優先順位を意識します。

繰返しは、初期値・継続条件・更新式の3点を確認します。最大の事故は「何回回るか」を感覚で決めることです。

i = 1,2,3 の3回なのか
i = 0,1,2,3 の4回なのか
境界を必ず書き出す。
配列・二次元配列・文字列

配列は同種のデータを添字で管理する構造。問題では「添字が0始まりか1始まりか」が最重要です。

二次元配列は行×列。座標、行列、表、画像などを扱えます。A[i][j]のiとjの意味を問題文から確定させます。

疎行列は0が非常に多い行列。全要素を保存する代わりに「行番号・列番号・値」など非零要素だけを持つことでメモリを節約できます。

文字列処理では長さ、部分文字列、比較、走査位置を追います。終端条件と1文字ずれ（off-by-one）に注意。

探索：線形探索と二分探索
線形探索二分探索
考え方先頭から順番に探す中央と比較し範囲を半分に絞る
前提ほぼ不要整列済みであること
計算量O(n)O(log n)

二分探索ではlow、high、midの更新を表にして追います。見つからない場合の終了条件も重要です。

整列：選択ソートと挿入ソート

選択ソート：未整列部分から最小（最大）を探し、先頭と交換。ポイントは「毎回、残り全部から選ぶ」。

挿入ソート：左側を整列済みとみなし、新しい要素を適切な位置へ差し込む。トランプを手札へ入れるイメージ。

見分け方： 「最小値を探して交換」→選択、「前の要素をずらして差し込む」→挿入。
スタック・キュー
スタックキュー
原則LIFO：後入れ先出しFIFO：先入れ先出し
操作push / popenqueue / dequeue
例関数呼出し、Undo、DFS待ち行列、BFS、印刷待ち
連結リスト・ポインタ

単方向連結リストでは各ノードが「値」と「次ノードへの参照」を持ちます。headは先頭、tailは末尾への参照です。

先頭挿入は新ノードのnextを旧headへ向け、headを新ノードへ更新。末尾挿入では旧tail.nextを新ノードへ向け、tailを新ノードへ更新します。

A→B→C→未定義/null

科目Bの鉄則： ノード名ではなく「各nextが今どこを指しているか」を図にする。代入順で結果が変わります。

木構造・二分木・走査

木は階層構造。最上位がroot、末端がleaf。二分木は各ノードの子が最大2つです。

代表的な走査は、前順（root→左→右）、間順（左→root→右）、後順（左→右→root）。問題のOrder関数では「出力処理が再帰呼出しの前・間・後のどこにあるか」を見ます。

配列表現では、0始まりなら左子2i+1、右子2i+2が典型。1始まりなら左2i、右2i+1です。

再帰

関数が自分自身を呼び出す処理。必ず終了条件（base case）が必要です。

追い方は「呼び出しで下る段階」と「returnで戻る段階」を分けます。スタックに呼出し状態が積まれるイメージが有効です。

ハッシュ法・衝突・負荷率

ハッシュ関数でキーから配列位置を求め、平均的に高速な検索を実現します。典型はkey mod 表サイズ。

衝突は異なるキーが同じ位置になること。オープンアドレス法では別の空き位置を探します。ダブルハッシュでは2つ目のハッシュ関数を再探索幅に使います。

負荷率 = 格納済み要素数 ÷ ハッシュ表の大きさ。高すぎると衝突が増え、性能が落ちます。

4. CPU・メモリ・記憶装置

CPU・レジスタ・割込み

CPUは命令を取り出し、解読し、実行します。レジスタはCPU内部の非常に高速な小容量記憶領域です。

  • プログラムカウンタ：次に実行する命令の位置
  • 命令レジスタ：現在の命令
  • 汎用レジスタ：演算値・一時データ

割込みは、実行中の処理を一時中断して別処理へ移る仕組み。多重割込みでは、割込み処理中にさらに優先度の高い割込みを受ける場合があります。

ディスパッチは、実行可能状態のタスクへCPU使用権を渡す処理です。

リエントラント（再入可能）なプログラムは、複数の実行主体が同時・途中から利用しても安全なように設計されています。

RAM / ROM / DRAM / SRAM / Flash

キャッシュ・TLB・MMU・仮想記憶

キャッシュはCPUと主記憶の速度差を埋めます。時間的局所性（最近使ったものをまた使う）と空間的局所性（近くのものを使う）を利用します。

MMUは仮想アドレスと物理アドレスの変換を担い、TLBはそのページ変換情報を高速に参照するためのキャッシュです。

仮想記憶では主記憶に入り切らない内容を補助記憶と組み合わせて扱います。ページフォールトが多発するとスラッシングにつながります。

例：1920×1080、24bitカラーなら約6.22MB（単純計算）。問題ではKiB/MiB換算やダブルバッファ等の条件を確認します。

磁気ディスクとRAID

トラックは同心円状の記録領域、セクタはトラックの分割単位、シリンダは複数面の同じ半径位置のトラック群です。

5. OS・ソフトウェア

OSの役割・プロセス・タスク

OSはCPU、メモリ、入出力装置、ファイルなどの資源を管理し、アプリケーションに共通機能を提供します。

プロセス／タスクは実行中のプログラムを管理する単位として扱われます。状態は典型的に「実行可能 → 実行 → 待ち」などを遷移します。

CPUスケジューリング・プリエンプティブ

プリエンプティブ：OSが実行中タスクからCPUを強制的に取り上げられる。ノンプリエンプティブ：タスクが自発的にCPUを手放すまで基本的に切替えない。

ディスパッチは選んだタスクにCPUを割り当てる瞬間の処理です。

デッドロック

複数処理がお互いの資源解放を待ち、永久に進めなくなる状態。DBロックでもOS資源でも出ます。「AはXを保持してY待ち、BはYを保持してX待ち」の循環が典型です。

コンパイラ・コールドスタート

コンパイラはソースコードを機械語などへまとめて変換します。インタプリタとの対比が頻出です。

コールドスタートは電源投入など、初期状態からシステムを起動すること。既存状態を利用するウォームスタートと対比されます。

6. データベース

DBの中心軸： 「表の構造」「SQLで取り出す」「同時更新を安全にする」「障害から戻す」の4本柱で整理すると混乱しません。
関係データベース・キー・正規化

関係データベースはデータを表（テーブル）で表現します。行がレコード、列が属性（フィールド）。

主キーは行を一意に識別し、外部キーは別テーブルの主キー等を参照して関係を作ります。参照制約は「存在しない親を指す子」など不整合を防ぎます。

正規化は重複や更新時の不整合を減らすために表を整理する考え方。試験では関数従属性、部分関数従属、推移的関数従属などが絡みます。

SELECT / WHERE / JOIN 
SELECT 部署名, 氏名
FROM 社員
INNER JOIN 部署 ON 社員.部署ID = 部署.部署ID
WHERE 社員.在籍 = 1;

WHEREは行を絞る。JOINは複数表を関連付ける。INNER JOINは結合条件を満たす行だけ残します。

JOINの読み方： ①FROM/JOINで「どの表をつなぐか」→②ONで「何を同一視するか」→③WHEREで「どの行を残すか」。
GROUP BY と HAVING 
SELECT 部署ID, COUNT(*)
FROM 社員
GROUP BY 部署ID
HAVING COUNT(*) >= 5;

GROUP BYは同じ値ごとに集約。HAVINGは集約後のグループを絞ります。WHEREは集約前の個々の行を絞る、と覚えると強いです。

サブクエリ

SQLの中に別のSELECTを入れる方法。まず内側のSELECTが何を返すかを日本語にし、その結果を外側でどう使うか考えます。

結合アルゴリズム：ソートマージ結合

結合キーで両入力をソートし、先頭から比較しながら一致する行を結合します。ハッシュ結合などとの違いを概念で理解します。

ロールバックは未完了トランザクションの変更を取り消す方向。ロールフォワードはバックアップ後にログを適用し、障害直前へ進める方向です。

7. ネットワーク

OSI基本参照モデルとTCP/IP
OSI層役割のイメージ例
7 アプリケーション利用者に近い通信機能HTTP, SMTP, DNS
4 トランスポート端末間の通信制御TCP, UDP
3 ネットワーク異なるネットワーク間の配送IP, ルータ
2 データリンク同一リンク内のフレーム転送Ethernet, MAC

OSIは7層、TCP/IPモデルはより少ない層にまとめます。試験では「どの層の仕事か」を聞く問題が多いです。

IPv4・サブネットマスク・CIDR

IPv4は32bit。サブネットマスクはネットワーク部とホスト部の境界を示します。/26なら先頭26bitがネットワーク部、残り6bitがホスト部。

ホスト部が h bit → アドレス数 2^h

典型的なIPv4サブネットではネットワークアドレスとブロードキャストアドレスを除くため、利用可能ホスト数は2^h - 2とする問題が多いです。

ネットワークアドレスはIPアドレスとサブネットマスクのANDで求めます。

RARP

RARP（Reverse Address Resolution Protocol）は、MACアドレスなどからIPアドレスを得る古い仕組み。現在はDHCP等が一般的ですが、試験用語としてARPとの方向の違いを整理します。

CSMA / CSMA/CD / Ethernet

CSMAは送信前に通信路が空いているか確認する考え方。CSMA/CDはさらに衝突（Collision）を検出して再送を行う方式で、従来の共有型Ethernetで使われました。

HTTP / HTTPS / Proxy / Port

HTTPはWeb通信のアプリケーション層プロトコル。HTTPSはHTTPをTLSで保護します。

プロキシはクライアントの代理として外部へアクセスします。キャッシュ、アクセス制御、匿名化などの目的があります。

ポート番号は同一ホスト上のどのアプリケーション／サービス宛てかを識別します。

IPsec

IP層で通信を保護する仕組み。VPNで使われます。HTTPS/TLSが主にアプリケーション通信を保護するのに対し、IPsecはIPパケットレベルで保護する点を区別します。

ポートスキャン・プライバシーセパレータ

ポートスキャンは対象ホストのポートへ接続を試み、開いているサービスを調べる行為。管理目的にも攻撃準備にも使われます。

プライバシーセパレータは無線LANアクセスポイント配下の端末同士の直接通信を制限する機能。公衆・ゲストWi-Fiで端末間攻撃を抑えるのに有効です。

8. 情報セキュリティ・暗号

共通鍵・公開鍵・ハイブリッド暗号
共通鍵暗号公開鍵暗号
鍵暗号化と復号で同じ秘密鍵公開鍵と秘密鍵のペア
速度高速比較的重い
課題鍵配送計算コスト、公開鍵の真正性
例AESRSA、楕円曲線系

ハイブリッド暗号は「公開鍵系でセッション鍵を安全に合意・配送し、その後は高速な共通鍵暗号で大量データを暗号化」という組合せです。

AES / RSA / DH / ECDH

AES：代表的な共通鍵ブロック暗号。RSA：公開鍵暗号・署名に使われる代表方式。Diffie-Hellman（DH）：盗聴される通信路上で共有秘密を合意する鍵交換方式。ECDHは楕円曲線上のDHです。

重要： 「公開鍵暗号」と「鍵交換」は同じではありません。DH/ECDHは、相手の公開情報を用いて共有秘密を合意する仕組みです。
ハッシュ・SHA-256・MAC

ハッシュ関数は任意長データから固定長の値を作る一方向的な関数。SHA-256は代表例です。

暗号化は鍵を使って元に戻せることが目的。ハッシュは通常、元データへ戻すことを目的にしません。

MAC（Message Authentication Code）は共有秘密を使い、メッセージの改ざん検出と送信者認証に使います。

デジタル署名

送信者が秘密鍵で署名し、受信者が公開鍵で検証します。主に真正性・完全性・否認防止を支えます。秘密を隠す「暗号化」と目的が違います。

PKI / CA / RA / 証明書 / CRL / OCSP

PKIは公開鍵と本人・組織の結び付きを証明書で管理する仕組み。CAは証明書を発行・署名する認証局、RAは申請者確認など登録業務を担う役割です。

CRLは失効証明書リスト、OCSPは証明書の失効状態をオンラインで問い合わせる仕組み。

TLS / HTTPS / Cipher Suite / PFS

TLSは通信の盗聴・改ざん等を防ぐためのプロトコル。HTTPSはHTTP over TLSです。

Cipher Suiteは通信で使う暗号関連方式の組合せを表します。TLSのバージョンによって表し方は異なります。

前方秘匿性（PFS）は、長期秘密鍵が将来漏えいしても、過去のセッション鍵まで簡単に復元されない性質。エフェメラルなDH/ECDHが重要です。

多要素認証

認証要素は「知識（PIN等）」「所持（ICカード等）」「生体（指紋等）」に大別。異なる種類の要素を2つ以上使うのが多要素認証です。ICカード＋PINは所持＋知識。

攻撃：ゼロデイ・総当たり・SQLi・ランサムウェア
  • ゼロデイ攻撃：修正が用意されていない脆弱性などを突く。
  • ブルートフォース：候補を総当たりする。
  • SQLインジェクション：入力値を介して意図しないSQLを実行させる。対策の中心はプレースホルダ／パラメータ化クエリ。
  • ランサムウェア：データ暗号化・窃取等を行い身代金を要求。バックアップ、脆弱性対策、権限最小化、監視など多層防御が重要。
暗号解読の用語

差分解読は入力差分と出力差分の偏りを利用する解析、線形解読は暗号内部の関係を線形近似して偏りを利用する解析。代数的解読は暗号を数式系として表現して解く考え方です。FEでは細部より「暗号方式への解析手法」という位置付けを押さえます。

9. システム開発・設計

UML・クラス・インスタンス

UMLはシステムの構造や振る舞いを図で表す標準的なモデリング記法です。

クラスは設計図・型、インスタンスはそのクラスから作られた具体的な実体。たとえば「自動車クラス」に対し「自分の白い車」がインスタンス。

アクティビティ図は処理・業務の流れ、分岐、並行処理などを表すのに向きます。

DFD / ER図 / 決定表 / フローチャート

DFDはデータの流れ、処理、データストア、外部実体を表します。処理手順そのものより「データがどこからどこへ動くか」が中心。

ER図はエンティティと関係を表し、DB設計で使います。

決定表は条件の組合せと実行する処理を表形式で整理します。条件が複数あり、組合せ漏れを避けたいときに有効。

フローチャートは処理順序を記号で表します。

XMLとDTD

XMLはタグを使って構造化データを表現します。DTD（Document Type Definition）は、そのXMLで使える要素や構造の規則を定義します。

IDE / EUC / プロトタイピング / SOA / 3層構成

IDEは編集・ビルド・デバッグ等を統合した開発環境。

EUCはEnd User Computingで、利用部門自身がITを活用して業務処理等を行う考え方。

プロトタイピングは試作品を早期に作って要求を確認・改善する方式。

SOAは業務機能をサービスとして疎結合に組み合わせる考え方。

3層クライアントサーバは典型的にプレゼンテーション層、アプリケーション層、データ層へ分けます。

10. テスト・品質・要件

カバレッジ

命令網羅：全命令を少なくとも1回。分岐網羅：各判定の真・偽を少なくとも1回。条件網羅：複合条件内の各条件が真・偽を取るようにする、など。

「何を全部通すのか」を見れば区別できます。

受入テスト・要件定義

要件定義は「システムに何を求めるか」を明確にする工程。受入テストは利用者・発注者側の視点で、要求を満たすか確認する最終段階のテストです。

テストと監査

テストはシステム・ソフトウェアが仕様通り動くか確認。監査は独立・客観的な立場で、統制や管理が適切かを評価します。目的と立場が違います。

11. プロジェクト・サービス・監査・ISMS

プロジェクトマネジメント

期限・コスト・品質・スコープ・リスク・資源などを管理し、目標達成へ導きます。FEではWBS、進捗、リスク、見積りなど基本概念が出ます。

サービスマネジメントとインシデント管理

ITサービスを安定して提供し、継続的に改善する活動。インシデント管理は障害・サービス中断等から、できるだけ早く正常サービスへ復旧させることが第一目的です。根本原因究明を主目的とする問題管理とは区別。

コンティンジェンシー計画

災害・重大障害など非常事態に備えた対応計画。通常運用の手順ではなく、「想定外・緊急時にも事業を守る」ための備えです。

システム監査

情報システムに関するリスクへの管理・統制が適切かを、独立・客観的に点検・評価します。開発者自身のテストとは立場が異なります。

ISMS

ISMS（Information Security Management System）は情報セキュリティを組織的に管理・継続改善する仕組み。資産・リスクを把握し、対策を選び、運用し、評価・改善します。

組織・資産把握→リスク評価→対策→運用→評価・改善

12. システム戦略・経営・会計・法務

BI / EA / BSC

BI（Business Intelligence）：企業内外のデータを分析し、意思決定に活用。

EA（Enterprise Architecture）：組織全体を業務・データ・アプリケーション・技術などの観点から体系化し、全体最適を目指す考え方。

BSC（Balanced Scorecard）：財務だけでなく、顧客、内部プロセス、学習と成長など複数視点で戦略を管理します。

SCM / MRP

SCMは調達から生産、物流、販売までサプライチェーン全体を最適化。

MRPは生産計画や部品表、在庫などから必要資材の量と時期を計画します。

キャッシュフロー計算書

現金及び現金同等物の増減を、営業・投資・財務活動などに分けて示します。営業活動によるCFは本業の事業活動による現金の流れ。

デルファイ法・ワークサンプリング

デルファイ法は複数の専門家へ匿名的に意見を求め、フィードバックを繰り返して予測・合意を形成する方法。

ワークサンプリング法はランダムな時点で作業状態を観測し、作業時間割合などを統計的に推定します。

契約不適合責任・旧「瑕疵担保責任」

契約内容に適合しない目的物・成果物が引き渡された場合に、追完、代金減額、損害賠償、解除などが問題となる考え方です。現行法の問題では「契約不適合責任」という用語を中心に確認します。

レジスタ／割込み／ディスパッチ／プリエンプティブ／リエントラントを1枚の関係図で。

暗号

アルゴリズム

暗記より手トレース。配列・リスト・木・ハッシュを図にする。

15. 20問の自己確認クイズ

すべてオリジナル問題。答えはタップして確認。

Q1. /26 のIPv4サブネットでホスト部は何bit？
6bit。IPv4は32bitなので 32−26=6。
Q2. 配列が整列済みであることが前提の代表的探索は？
二分探索。探索範囲を半分ずつ絞る。
Q3. DFSに自然に対応するデータ構造は？
スタック。再帰も内部的には呼出しスタックを利用する。
Q4. WHEREとHAVINGの大きな違いは？
WHEREは集約前の行、HAVINGはGROUP BY等で集約後のグループを絞る。
Q5. 共有ロック同士は共存できる？
原則できる。共有ロックは読み取り用。
Q6. RAID5を4台の同容量ディスクで組む典型的な実効容量は？
3台分。(N−1)台分。
Q7. SRAMの典型用途は？
キャッシュメモリ。高速だが高価。
Q8. TLBが高速化するものは？
仮想アドレス→物理アドレスのページ変換情報の参照。
Q9. XORが1になるのは？
2つの入力が異なるとき。
Q10. デジタル署名の主目的は秘密性？
いいえ。主に真正性・完全性・否認防止。
Q11. AESは共通鍵か公開鍵か？
共通鍵暗号。
Q12. ECDHは主に何をする？
共有秘密／セッション鍵材料を合意する鍵交換。
Q13. ICカード＋PINはなぜ多要素？
所持要素＋知識要素という異なる種類を組み合わせるから。
Q14. SQLインジェクション対策の代表は？
プレースホルダ／パラメータ化クエリ。
Q15. インシデント管理の第一目的は根本原因究明？
いいえ。まずサービスを迅速に正常復旧すること。
Q16. DFDは何を中心に描く？
データの流れと処理・データストア・外部実体。
Q17. BSCの特徴は？
財務だけでなく複数の視点から戦略を管理する。
Q18. MRPは何を計画する？
生産に必要な資材の量と必要時期。
Q19. 再帰関数で絶対必要なものは？
終了条件（base case）。
Q20. 科目Bで最も危険な解き方は？
コードを雰囲気で読み、変数・添字をトレースせず答えること。

16. 1〜3分で見返す超圧縮復習

  • 科目B： 添字・境界・代入順・ポインタ・再帰の戻りを手で追う。
  • 二分探索： 整列済み、O(log n)。
  • DFS： スタック／再帰。BFSはキュー。
  • ハッシュ： 衝突と負荷率。modだけで終わらない。
  • DRAM/SRAM： 主記憶＝DRAM、キャッシュ＝SRAM。
  • TLB： アドレス変換のキャッシュ。
  • RAID5： 分散パリティ、典型容量(N−1)台分。
  • DB： WHERE＝集約前、HAVING＝集約後。Sロック同士は共存。
  • ネット： IPはL3、TCP/UDPはL4、HTTPはL7。/26→ホスト部6bit。
  • 暗号： AES＝共通鍵、RSA＝公開鍵系、DH/ECDH＝鍵交換、SHA-256＝ハッシュ。
  • 署名： 秘密性ではなく真正性・完全性・否認防止。
  • PKI： CA＝証明書、CRL/OCSP＝失効確認。
  • インシデント管理： まず復旧。根本原因は問題管理。
  • UML/DFD/ER： 振る舞い・データ流・DB関係を見分ける。
