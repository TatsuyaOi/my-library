# 学習教材MVPの運用

## 正本と生成物

新しい通常教材は `content/<slug>/content.md` と `meta.json` を正本とする。
本文はH2から開始する。H1はメタ情報の題名から生成する。
画像は同じ教材の `assets/` に置く。本文の生HTMLは実行せず文字として表示する。
対応形式は通常のCommonMarkと表。数式はUnicodeまたはコード表記とし、LaTeXレンダラー、クイズ採点、コース生成、単一HTML版は今回の対象外。

既存資料・Inbox資料のスキーマは変更しない。新教材だけが `schemas/learning-meta.schema.json` を使用する。
バリデーターはこのMVPスキーマの型・必須項目・列挙値・日付・タグ・slugとフォルダ一致・カテゴリ存在を検査する。
教材カテゴリーは既存の `library.config.json` のキーを指定し、URLはカテゴリーから独立して維持する。

## ビルドと確認

Python 3.10以上を使用する。Actionsは既存どおり3.12。

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p 'test_*.py' -v
python scripts/build.py --preview
python -m http.server 8000 --bind 127.0.0.1 --directory _preview
```

ブラウザで `http://127.0.0.1:8000/` を開く。トップの検索、勉強カテゴリから教材に移動できる。
新しい共通資産をGit未追跡のまま実行すると公開出力にコピーされないため、開発時は該当ファイルを正確なパスでステージする。
通常運用は `python scripts/build.py` だけで公開用 `_site` を生成する。
`--preview` は公開用を生成した後、下書きを含む `_preview` を別に生成する。公開用索引に下書きは混ぜない。
両方の出力ディレクトリは生成物でありGit管理しない。生成HTMLを編集せず、正本を変更して再実行する。

## 2件目の追加

1. 既存教材フォルダを手本に、新しい `content/<slug>/` を作る。
2. 本文・題名・概要・タグ・日付を実際の教材に合わせ、slugとフォルダ名を一致させる。
3. 最初は `status: draft`、`publish: false`。機密情報はGitHubへ保存しない。
4. プレビューを生成し、360/390/768/1280pxと拡大・印刷、目次、リンクを確認する。
5. 対象ファイルをステージしてテスト、ビルド、専用ブランチへのコミット、PRの順で進める。

## 公開境界

`publish: true` かつ `status: active` の教材だけを公開索引と `_site/content/` に含める。
`publish: true` と下書き・アーカイブの併用は設定エラーとして停止する。
教材原本とmeta.jsonはPagesへコピーせず、生成HTMLと画像だけを出力する。
公開済み教材を非公開に戻した場合も再ビルドで古い出力を除去する。
`publish: false` はGitHub上での秘匿を意味しない。今回の試験教材は公開資料と説明用の例だけで構成している。

既存のmainマージ後デプロイは維持する。PRでは検証のみ。マージはユーザーが行う。
共通資産は公開されるが、下書き本文・画像は公開出力へ入らない。
現行の旧資料の公開方式は維持し、新教材の公開フラグを旧資料へ一律に適用しない。

## 依存関係と検証範囲

Markdown変換にはMITライセンスのmarkdown-it-py 4.0.0とmdurl 0.1.2を使用する。
サーバーフレームワーク、CDN、ブラウザ側の新規JavaScript依存は追加しない。
既存の小さな静的生成処理にPython依存を2件追加し、ローカルとActionsで版を固定する。
教材の内部リンク・画像・アンカーは生成後に検査し、大文字小文字の違いもエラーにする。
外部リンクの継続的な到達確認と内容の正確性は、自動テストだけでは保証しない。
