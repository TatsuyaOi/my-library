## 12. グラフ・模式図・画像の使い分け

### グラフ
数値データが存在し、比較・傾向・分布・関係性を視覚化した方が理解しやすい場合に使用してください。

- 時系列 → 折れ線
- カテゴリ比較 → 棒
- 相関 → 散布図
- 構成比 → 構成比表現。ただし項目が多い場合は棒グラフ等を優先
- 複数指標 → 読みやすさを優先し、無理に1グラフへ詰め込まない

根拠となる数値がない場合は、架空のグラフを作成しないでください。

### SVG模式図
以下のような構造説明に積極的に使用してください。

- 層構成
- 装置構成
- メカニズム
- 原因と結果
- 材料間の関係
- 工程フロー
- システム構成
- 概念整理

模式図は実測画像と誤認されないよう、必要に応じて「模式図」「概念図」と明記してください。

### 画像
画像が理解を実質的に改善する場合に使用してください。

- 実物写真
- 観光地
- 製品
- 外観
- 実験画像
- 代表的な視覚イメージ

入力資料に画像がある場合は、その意味を踏まえて適切な位置へ配置してください。

実画像が存在しない場合に、架空の実験写真・証拠画像・測定画像を捏造しないでください。その場合はSVG模式図や概念図を使用してください。

## 13. インタラクティブ要素の使用条件

JavaScriptによるインタラクションは、閲覧性を改善する場合に限定してください。

### 使用を推奨
- 長い詳細説明の折りたたみ
- タブ切り替え
- 大きな表の検索・絞り込み
- 学習用の「問題 → 解答表示」

### 原則不要

- 装飾だけのアニメーション
- 自動再生
- 過度なホバー依存
- スマートフォンで扱いにくい複雑操作

重要情報は、JavaScriptが動かない状況でも可能な限り読めるようにしてください。

## 14. 自己完結型HTMLの実装優先順位

可能な限り、1つのHTMLファイルだけで閲覧できる構成を優先してください。

優先順位：

1. CSSは `<style>` に内包
2. JavaScriptは `<script>` に内包
3. 模式図はインラインSVG
4. 小規模アイコンはSVGまたはCSS
5. 画像を埋め込む必要がある場合は、環境が許せばData URI / Base64等を検討
6. 外部ライブラリは、本当に必要な場合だけ使用
7. CDN依存は可能な限り避ける

Chart.js、Plotly等を使う場合も、外部依存による利点と自己完結性を比較し、目的に適した方法を選んでください。

ネット接続が必要な地図・動画・Web埋め込みなどを使用する場合は、オフラインでは利用できないことが分かるようにしてください。

## 16. Markdown版とHTML版の整合性

両形式は、表現方法が異なっても **情報量・意味・結論を実質的に一致** させてください。

- Markdown版：編集・保存・AI再利用向け
- HTML版：人間が閲覧する完成資料向け

HTML版では、Markdown版の文章をそのまま配置するのではなく、必要に応じて表・グラフ・模式図・カード等に再構成して構いません。

ただし、HTML版だけ重要な事実を追加したり、Markdown版にある重要情報を省略したりしないでください。
