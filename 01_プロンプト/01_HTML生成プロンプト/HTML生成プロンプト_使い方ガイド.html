MY LIBRARY PROMPT GUIDE

HTML生成プロンプト
使い方ガイド

「完成済みHTMLをMy Library対応へ変換する」と 「画像を見やすいHTMLにする」の2つを、同じプロンプトで使い分ける方法を説明します。

A：HTMLを変換
B：画像をHTML化

1

このプロンプトで何ができる？

1つのプロンプトで、主に次の2つの使い方ができます。

モードA：HTMLをMy Library対応化 すでに完成しているHTMLを、内容を変えずにGitHub Pages・My Libraryで管理しやすい形へ変換します。
モードB：画像をHTML化 1枚または数枚の画像を、スマホで見やすく拡大できる1ファイルHTMLへまとめます。
ポイント： 「何の処理をするか」は、添付したファイルからAIが基本的に自動判定します。
2

最短の使い方

① マスタープロンプトをChatGPT / Codexへ貼る ↓ ② 変換したいHTMLまたは画像を添付 ↓ ③ 必要なら保存先カテゴリ・小分類だけ変更 ↓ ④ 実行 ↓ ⑤ 完成したHTMLをダウンロード ↓ ⑥ My Libraryの該当フォルダへ保存 ↓ ⑦ Commit → Push

毎回プロンプト全文を書き換える必要はありません。

基本は「ファイルを添付して、末尾の指定だけ変える」
3

モードA：完成済みHTMLを変換する

すでに教材・思想ノート・旅行資料などのHTMLが完成しているときに使います。

何をしてくれる？

  • 元の文章や情報は原則そのまま保持
  • My Library用メタ情報を追加
  • GitHub Pagesで問題になるローカルパスを修正
  • スマホではみ出す画像や表を調整
  • 必要なら添付画像をHTML内へ埋め込み
  • GitHub Pagesで動く1ファイルHTMLへ整備
重要： 内容そのものを「もっと分かりやすく書き直す」プロンプトではありません。 元HTMLの内容を保ったまま、My Library向けに整える用途です。

使うときのイメージ

マスタープロンプトを使用してください。

添付したHTMLをMy Library対応にしてください。

保存先カテゴリ：12_簿記
小分類：決算
library-pinned：false
4

モードB：画像を見やすいHTMLにする

画像しか持っていないときに使います。

例えば、次のような資料です。

  • ChatGPTで生成した1枚図解
  • 勉強用のまとめ画像
  • 複数ページの旅行プラン画像
  • スクリーンショット資料
  • 表・概念図・フローチャート画像

1枚の場合

画像1枚 ↓ 画像データをHTML内部へ埋め込み ↓ スマホ幅いっぱいに表示 ↓ タップで拡大 ↓ 1ファイルHTMLとして完成

複数枚の場合

画像1 画像2 画像3 ↓ 添付順に並べる ↓ 各画像を拡大可能にする ↓ 画像番号を表示 ↓ 1つのHTMLへまとめる
数枚程度なら画像もHTML内部へ入るため、 「HTMLファイル1個だけ」をGitHubへ保存すれば済みます。
5

毎回どこを変更する？

マスタープロンプトの最後にある「今回の指定」を変更します。

処理モード：
自動判定

保存先カテゴリ：
［例：12_簿記］

小分類：
［例：決算／画像資料／未分類］

library-pinned：
false

出力方式：
完成HTMLを1ファイル

画像の扱い：
1枚または数枚の場合はHTML内へ埋め込む

元HTMLの内容：
変更禁止
項目どう設定する？
保存先カテゴリGitHubのフォルダ名を書く
小分類カテゴリ内部の分類を書く
library-pinned通常は false。重要資料だけ true
処理モード基本は「自動判定」のまま
画像の扱い通常はそのままでOK

具体的な使い方

例1：完成済みの簿記HTML

添付

貸倒引当金.html

今回の指定

保存先カテゴリ：12_簿記
小分類：決算
library-pinned：false

完成後は次へ保存します。

my-library/
└─ 12_簿記/
   └─ 貸倒引当金.html

例2：哲学の1枚画像

添付

ストア派まとめ.png

今回の指定

保存先カテゴリ：01_哲学
小分類：ストア派
library-pinned：false

画像がHTML内に埋め込まれ、例えば次のようなファイルになります。

ストア派まとめ_画像資料.html

例3：旅行画像が3枚

3枚をまとめて添付し、

保存先カテゴリ：21_旅行

library-pinned：true

と指定します。3枚を順番に見られる旅行資料HTMLとしてまとめられます。

保存先カテゴリ：00_マニュアル
小分類：HTML運用
library-pinned：true
7

完成HTMLをGitHubへ入れる

HTMLが完成したら、保存先カテゴリへ置きます。

my-library
├─ 00_マニュアル
├─ 01_哲学
├─ 11_基本情報
├─ 12_簿記
├─ 21_旅行
├─ 31_仕事
├─ 41_AI
└─ 99_その他
完成HTMLを保存 ↓ GitHub Desktop ↓ Summaryを入力 ↓ Commit to main ↓ Push origin ↓ GitHub Actions ↓ library.json 自動更新 ↓ My Libraryへ自動表示
index.htmlやlibrary.jsonを手動で編集する必要はありません。 HTMLを正しいフォルダへ入れてPushすれば、自動化システムが一覧へ追加します。
8

使うときの注意点

完成HTMLは「内容変更禁止」

モードAでは、既存HTMLを教材として改善するのではなく、GitHub Pages対応へ整備する目的です。

画像が多すぎる場合

画像をすべてBase64で埋め込むとHTMLが非常に大きくなることがあります。その場合はAIがHTML＋imagesフォルダのZIP方式へ切り替えることがあります。

外部ファイルがあるHTML

HTMLが画像・CSS・JavaScriptなどを別ファイルで参照している場合、それらも一緒に添付した方が確実です。

HTMLだけ添付し、HTML内で参照している画像が手元にない場合、 AIは存在しない画像を勝手に作ることはしません。

ローカルパス

次のような記述はGitHub Pagesでは使えません。

C:\Users\...
file:///C:/...
D:\資料\画像.png

マスタープロンプトは、このような問題を検出して修正する想定です。

9

おすすめの運用方法

このマスタープロンプト自体を、My Libraryのマニュアルとして保存しておくと便利です。

00_マニュアル ├─ My Library 運用説明書.html ├─ HTML生成プロンプト 使い方ガイド.html └─ My Library対応HTML生成プロンプト.md

普段は次のように使い分けます。

やりたいこと添付するもの
既存教材をGitHub対応完成HTML
1枚図解を保存PNG / JPG / WebP 1枚
画像資料集を作る画像を数枚
HTML＋画像をまとめるHTML＋使用画像
HTMLを作る → My Library形式へ変換 → 保存 → Commit → Push
10

実行前チェックリスト

  • マスタープロンプトを貼った
  • 変換したいHTMLまたは画像を添付した
  • 保存先カテゴリを指定した
  • 必要なら小分類を指定した
  • 重要資料だけ pinned=true にした
  • 完成HTMLをダウンロードした
  • 正しいMy Libraryフォルダへ保存した
  • GitHub DesktopでCommitした
  • Push originした
  • My Libraryで表示を確認した

迷ったとき

細かい指定が分からなければ、保存先カテゴリだけ決めて、残りは「自動判定」のままでも構いません。

最も簡単な指示は、 「添付したファイルを、このマスタープロンプトに従ってMy Library対応HTMLにしてください」 です。
