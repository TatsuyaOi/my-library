理解優先・曼荼羅型資料作成マスタープロンプト v2.0

# 理解優先・曼荼羅型資料作成マスタープロンプト v2.0

作成日：2026-09-14  
用途：既存の説明・技術情報・検討結果を、正確で読み返しやすい図解資料へ再構成するための汎用指示。  
今回の成果物は作成プロンプトであり、完成画像や読者実験の結果ではない。

## 1. 再設計の結論

資料の品質を「1枚にどれだけ入ったか」「何枚以内か」「中央から放射状か」で判断しない。読者が主題を把握し、関係を理解し、必要な情報を探せて、誤解せずに説明・判断できることを優先する。

行政資料風の曼荼羅型ポンチ絵の長所である、全体像、関係の一覧性、複数観点の同時提示は残す。ただし、放射状配置、枠の数、色数、ページ数、縦横比は固定しない。構造を見せる全体図と、説明を担う詳細ページを必要に応じて組み合わせる。

「網羅的」とは、すべてを同じ大きさで同じ画面へ詰め込むことではない。重要な情報・成立条件・例外を、資料全体の中で失わず、所在が分かる状態をいう。

### 以前のルールからの変更

| 以前の設定 | 新しい扱い | 判断理由 |
|---|---|---|
| 合計6枚以下 | 上限なし。依頼で明示された場合のみ制約化 | 枚数を守るための縮小・欠落を防ぐ |
| 全ページ3:4 | スマホ向け静止画の初期候補。内容に合わせて変更 | 縦長が比較や大型構造図に常に有利とは限らない |
| 主要ブロック4〜6個 | 意味のまとまりから決める | 個数合わせで論点を無理に分割・統合しない |
| 原則1〜2列 | 画面幅で読める場合の候補 | 列数より実表示での可読性を優先 |
| 中央に共通テーマ | 中央配置に説明上の意味がある場合だけ採用 | タイトルの重複や矢印の混雑を避ける |
| 下部に次の行動 | 理解・参照用なら結論、条件、要点でもよい | 行動提案を必要としない資料にも対応 |
| 詳細は拡大して読む | 補足の拡大は可。主要説明まで拡大必須なら再構成 | スマホでの往復操作を減らす |
| すべて同じ説明順 | 同種の比較対象は統一、異種の説明は適切な型へ | 原理・手順・比較の違いを保つ |

## 2. 使い方

次の「実行用プロンプト」全体をコピーし、入力欄にテーマを記入する。整理対象の文章・画像・ファイルを添える。添付ファイル全体を渡し「このプロンプトに従って作成」と指示してもよい。

このファイル自体の改訂を依頼された場合は、プロンプトの実行と混同しない。未指定項目は妥当な仮定を置いて進め、重大な意味の違いが生じる場合だけ確認する。

## 3. 実行用プロンプト

```text
# 理解優先・曼荼羅型資料の設計と制作

/goal
提供された内容を、正確で、理解しやすく、必要な情報を探しやすい資料へ再構成する。
曼荼羅型ポンチ絵の一覧性を活用しつつ、内容に適した図・表・文章を選ぶ。
読者は資料単独で、主題、主要な関係、成立条件、未確認事項を把握できること。
固定の枚数・配置・情報密度を達成することを目的にしない。

/input
テーマ・整理対象：{必須。会話や添付から明らかなら補完する}
読者：{未指定なら、テーマの初学者〜中級者}
用途：{未指定なら、全体理解と後日の参照}
閲覧環境：{未指定なら、スマホ縦持ちを主、PCを補助}
成果物形式：{今回ユーザーが指定した形式。未指定なら目的から選ぶ}
保持すべき内容：{未指定なら、重要な主張・条件・数値・例外・根拠}
明示的な制約：{ページ数、比率、配色など。指定がなければ固定しない}
外部補足の範囲：{未指定なら理解に必要な最小限。追加分を区別する}

/priority
1. 内容の正確性、原文への忠実性、誤解の防止。
2. 読者にとっての理解しやすさ、論理の接続。
3. 重要情報の充足、根拠と条件の追跡可能性。
4. 閲覧環境での可読性、情報の探しやすさ。
5. 用途への適合、更新・再利用のしやすさ。
6. 視覚的一貫性、美観、簡潔さ。

下位の改善のために上位を損なわない。正確だが読めない場合は、
どちらかを諦めず、分割・階層化・形式変更で両立を図る。
新たな明示条件は優先するが、条件同士が両立しない場合は影響を説明する。

/source_audit
まず提供資料を読み、目的、対象、用語、主張、条件、数値、例外、根拠、
未確認事項を整理する。読み取れない部分は推測で埋めない。

意味のある情報単位に内部IDを付け、どのページ・節で扱うかを対応させる。
重要情報について、原文箇所、再表現、配置先、保持状態を確認する。
同じ意味の重複は統合できるが、条件や確度が異なる記述は統合しない。
原文に誤りの疑いがある場合は、忠実な引用と訂正・疑義を区別する。
編集のみで外部確認が不要なら、検索を作業量のために増やさない。
専門的・最新・高影響の追加主張は、適切な一次情報を確認する。

/understanding_questions
制作前に、読者が資料から答えられるべき問いを選ぶ。
例：何についての資料か／何が分かっているか／どうつながるか／
なぜそうなるか／何とどう違うか／どの条件なら成立するか／
何が未確認か／必要な情報はどこか。
全資料に同じ問いの数を強制しない。用途上必要な問いに絞る。

/structure_selection
内容の関係に合わせて構造を選ぶ。
・共通テーマと複数観点：曼荼羅型・中心と周辺の配置。
・工程、時間、操作：順序図・時系列・手順表。
・原因、媒介、結果：因果図。ただし未検証の因果は仮説と表示。
・選択肢の違い：同じ評価軸での比較表。
・部品、層、位置：構造図・断面図。
・条件で変わる判断：分岐図・条件表。
・数値の傾向：適切なグラフ。軸、単位、対象、期間を示す。
・定義、留意事項：短い文章や一覧。

図にする利点がない情報は文章・表で示す。
ASCII図は使わない。装飾だけの図を追加しない。
複雑な図は、一つの関係を理解できる単位に分ける。
複数形式を組み合わせても、用語・番号・関係の意味は統一する。

/page_architecture
まず主要な問いと情報の依存関係を整理し、その後にページ数を決める。
全体図が理解を助ける場合は、導入に全体図を置く。
詳細ページには全体図との対応名・番号を付け、迷子を防ぐ。
単純なテーマで不要な全体図・目次・まとめを増やさない。

1ページには、読者が持ち帰る中心的な問いまたは説明目的を設定する。
関連する複数論点を同じページで扱ってもよい。
因果の途中や条件と結論を分断しない。
分割時は必要な前提を短く再掲し、単独で見た際の誤解を防ぐ。
ページ順序は、前提知識と利用場面の双方から決める。
全体理解用の順路と、項目を直接探す参照経路を必要に応じて設ける。

情報が収まらない場合：
重複の整理、文章の明確化、表への変換、配置の変更、補足の分離、
ページ分割、形式変更を検討する。文字縮小だけで解決しない。
補足に移す場合も、主要な条件・警告・例外は該当する主張の近くに残す。

/accuracy
主要主張は必要に応じ、提供情報、確認済みの根拠、解釈、仮説、提案、
未確認を区別する。すべての文へラベルを乱用せず、誤認しやすい箇所に置く。

・相関、因果、工程順、分類、参照を同じ矢印で混同しない。
・AとB、BとCの関係だけから、AがCを引き起こすと断定しない。
・数値には単位、対象、比較基準、測定条件を必要な範囲で添える。
・原理と個別案件での実証を区別する。
・矛盾は時点、対象、定義、条件、版の違いを確認し、未解消なら併記する。
・模式図の厚さ、距離、色、位置が実寸や物理量を表さないなら明記する。
・見た目の大きさや色の強さで、根拠以上に重要度・確度を誇張しない。
・出典は対応する主張に短い参照番号を置き、詳細な出典へ追跡可能にする。
・存在しない出典、実験ID、測定値、検証結果は作らない。

/explanation
見出しは、何を説明しているか分かる具体的な表現にする。
初出の専門用語は短く定義し、表記を統一する。
抽象概念には、必要なら具体例・対比例を添える。
比喩は実際の仕組みとの対応と限界を示す。

原理説明なら「現象、仕組み、成立条件、具体例」、
検討資料なら「課題、原因候補、切り分け、評価」、
比較なら「共通軸、違い、条件別の適否」を候補とする。
不要な欄を埋めるために内容を作らない。
初学者向けの入口と中級者向けの詳細を階層化し、重複説明を増やさない。

/visual_design
読む入口と順序を明示する。通常は上から下、左から右を候補とするが、
図の意味に適した経路を優先する。
見出し・本文・補足の階層を区別し、本文は左揃えを基本とする。
行間、枠内余白、項目間余白を確保する。
色は分類や状態など役割を決め、同じ意味に同じ色を使う。
色以外にもラベル・形・線種を併用し、白黒でも主要関係が分かるようにする。
文字と背景の識別を確保し、写真や装飾の上へ重要な説明を重ねない。
日本語を読みやすい書体を選び、実際に利用できるフォントで確認する。

矢印は意味が必要なものだけ描き、必要なら「促進」「参照」「次の工程」
など関係名を付ける。交差や長い往復を避ける。
色、枠、矢印、アイコンを重複して使いすぎない。
装飾を減らしても論理が伝わることを確認する。

/mobile
比率は横：縦で明記する。3:4は縦長、4:3は横長である。
スマホ向け静止画では3:4を初期候補とするが、固定条件にはしない。
比較表や構造図で横長が適するなら、分割案との利点・欠点を比較して選ぶ。
HTMLなど可変レイアウトなら、固定比率より画面幅への追従を優先する。

主要説明は通常表示で読める設計を目指す。
補足のための拡大は許容するが、本文を読むたびに拡大・横移動が必要なら、
ページ分割や再配置を行う。高解像度化と文字の表示サイズを混同しない。

制作上の仮の検査幅として360〜430 CSS px程度を使ってよい。
これは万人への保証や規格値ではなく、想定スマホ表示を確認するための条件である。
画像の縮小後の文字サイズは、元文字サイズ×表示幅÷画像幅で概算できる。
例：幅1200pxの画像中の48px文字は、幅400px表示で約16px相当となる。
実際の読みやすさは書体、字形、行間、表示環境でも確認する。

/production
まず正確な原稿を固め、構成と関係を決めてから視覚化する。
文字・数値・正確な構造が多い資料では、編集可能な文字組みや決定的な作図を
選択肢に入れる。画像生成を使う場合も、日本語、数値、矢印、凡例を原稿と照合する。
能力や利用環境に応じて制作方法を選び、未利用の機能を使ったと述べない。
画像のみで情報の検索や再利用が難しい場合は、依頼範囲内で文字版も提案する。
不要な別形式の納品を勝手に必須化しない。

/discovery_review
完成候補の弱点を次の観点で探す。
1. 説明の空白：結論に至る途中の説明が抜けていないか。
2. 類推：他の資料形式を使うと理解しやすくならないか。破綻条件は何か。
3. 矛盾：本文、図、凡例、結論、出典で意味が食い違っていないか。
4. 異常：特に密なページ、極端に薄いページ、読みにくい枠がないか。
5. 交互作用：情報量と画面幅、色と確度、分割と文脈が悪影響を与えていないか。
6. 時間・版：更新日や条件が異なる情報を同一視していないか。
7. 未記録変数：読者の前提知識、閲覧端末、共有方法などで設計が変わらないか。

問題候補には、懸念、改善案、改善が成立する条件、確認方法を記す。
資料に無関係な材料実験や、数合わせの仮説ランキングは作らない。
発見候補と、実際に確認された欠陥を分ける。

/verification
検査を以下に分け、実施済み、未実施、適用外を明記する。
A. 内容照合：重要な主張・条件・数値・例外の欠落や改変がないか。
B. 論理照合：関係、因果の確度、説明順、図と本文が一致するか。
C. 表示確認：実際の出力で文字崩れ、欠け、重なり、細かすぎる文字がないか。
D. 用途確認：想定読者の問いに答えられ、目的の項目へ移動できるか。
E. 納品確認：指定形式のファイルが存在し、正常に読み出せて渡せるか。

机上で問いに答えられる確認と、実際の読者テストを区別する。
表示未確認なら実機で読みやすいと断定しない。
プロンプトの作成依頼では、完成画像の実機検査まで必須成果物にしない。
画像制作依頼では表示確認を省いて設計確認だけで代用しない。

/scoring
制作前に次の10項目、各10点、合計100点で評価する。
正確性／重要情報の充足／論理と説明／読者適合／構成の適応性／
可読性の設計または実表示／探索・参照性／根拠と不確実性／
制作・納品の実行性／検証と修正の具体性。

0〜3：欠落・重大矛盾。
4〜6：方針はあるが実行条件が不足。
7〜8：実行可能だが例外や検証が不十分。
9：主要条件を満たし、軽微な限界が残る。
10：今回の評価範囲で具体的な欠落を認めない。

評価対象がプロンプト設計なのか、完成資料なのかを明記する。
致命・重大な欠陥が残れば、合計点にかかわらず不合格。
必須の検査が未実施なら、該当条件を達成済みにしない。
目標は95点以上。最大5回まで、欠点の確認、実修正、影響箇所の再確認を行う。
初めて合格した時点で終了してよい。基準を緩めて95点に合わせない。
上限で未達なら点数と残る問題を明示する。

/output
依頼された完成物を先に渡す。
必要な範囲で、構成選択の理由、原文との対応、レビュー記録、未検証事項を添える。
ファイル単独でも目的、利用方法、前提が分かるようにする。
本文だけでダウンロードファイルを作ったことにしない。
```

## 5. 設計上の発見と反証

以下はデータで実証された効果ではなく、前の回答の設計を点検して得た改善候補である。

| 観点 | 発見した懸念 | 改善と、採用を見直す条件 |
|---|---|---|
| 説明の空白 | 網羅性の定義がなく、短文化による条件脱落を検出しにくい | 情報単位と配置先を照合。単純資料では短いチェックリストへ縮約 |
| 類推 | 放射型以外の比較表・手順図の利点を使えていない | 意味から形式を選択。全体関係が失われる場合は全体図を併設 |
| 矛盾 | スマホ可読性と高密度・固定枚数が衝突する | 数量を可変化。厳密な提出上限がある場合は制約として再評価 |
| 異常 | 特に密な1枠を基準に全体文字を小さくしうる | 局所的に分割・再配置。密度差だけで欠陥とは判定しない |
| 交互作用 | ページ分割で文字は大きくなるが因果の文脈が切れる | 前提の再掲と参照を付ける。ページ往復が増えるなら統合を比較 |
| 時間・版 | 過去の仮説と現在の観察結果が同じ確度に見える | 日付・版・状態を表示。時点が無関係なら追加表示は不要 |
| 未知変数 | 読者の知識と実表示幅が未設定 | 初期仮定を置き、表示と読者の問いで確認。実読者検査は別途 |

優先して確認するのは、①原文の重要情報保持、②矢印と確度の一致、③想定表示幅での主要説明の可読性。配色の好みよりも、誤解や欠落を減らす確認を先に行う。

## 6. 今回のレビュー記録

### 評価対象と固定基準

評価対象は、このMDに収録したプロンプトの設計品質。完成した図の視認性、理解速度、複数モデルの成功率ではない。実行用プロンプトの10項目・採点尺度を第1回から固定した。自己レビューであり、独立した第三者検証ではない。

### 第1回：初稿の点検と修正

初稿の欠点：枚数と比率を可変にしただけでは、原文の条件の保持を検査できない。高解像度とスマホ上の文字サイズも区別できていない。

修正：情報単位と配置先の照合、条件を主張の近くに残す規則、縮小後の文字サイズの概算、表示幅の仮定を追加。

再確認：長い技術資料でページを増やしても、情報の脱落と表示縮小を別々に検査できる。残る問題は、確度表現と版、方法選択の具体性。修正後90点。

### 第2回：反証と適用範囲の修正

欠点：因果と参照が同じ線になりうる。原文の誤りを忠実性の名で保存しうる。Hakkenの数量・材料実験要件を機械的に持ち込む余地がある。出力画像の文字検査が弱い。

修正：関係種別、原文と訂正の分離、日付・版、7観点の資料設計への適用範囲、原稿先行と生成後照合を追加。

再確認：未測定の原因候補は実証済みの矢印にならず、材料データがない今回の依頼で実験値を作らない。残る問題は、プロンプト評価と完成資料評価の検査境界。修正後94点。

### 第3回：検証範囲と納品条件の修正

欠点：将来の完成図の未実施検査を、今回のプロンプト納品の未完了条件にしうる。ページ分割が文脈を切る問題と、単純テーマでの管理過剰への対策が弱い。

修正：設計と実表示の採点対象を区別。実施済み・未実施・適用外を明示。分割時の前提再掲と、目次・全体図・管理表の縮約を追加。

再確認：プロンプト納品は設計検査で受入可能だが、将来の画像制作では表示検査が必要。単純な題材は1枚でもよく、長い題材は6枚を超えてもよい。修正後96点。重大な設計欠陥を認めず、3回で終了。
