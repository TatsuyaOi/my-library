# 4役分離・連続2回95点 Quality Gate 設計メモ

**Version 1.1 — 2026年8月27日生成**  
**主成果物：`four-role-quality-gate_prompt.md`**

## 1. 設計方針

今回の更新は、Adaptive型の「タスクに応じたRubric・分岐・改善ループ」を基礎にし、厳格採点型の次の要素を統合しています。

- Critical / Highに連動する得点上限制
- 95点Quality Gate
- 採点基準・配点・Severityの途中操作禁止
- 毎ROUNDのワースト5
- 回帰チェック
- 到達不能時の誠実な未達報告

さらに、自己採点の甘さを抑えるため、作成・批判・採点・最終承認を4役へ分離しました。

## 2. 比較した3構成

| 案 | 構成 | 強み | 弱み | 評価 |
|---|---|---|---|---:|
| A | 4役の直列レビュー | 分かりやすい | 同一AI内の採点アンカーが残る | 90 |
| B | 4役＋ブラインド採点 | 自己弁護と過去得点を遮断 | 1回だけの高得点が偶然でも通る | 94 |
| C | 4役＋ブラインド採点＋同一成果物の連続2回Gate | 安定性、再現性、採点操作耐性が最も高い | 実行負荷が高い | **98** |

統合最終版はCを採用しました。

## 3. 主要な追加設計

### 3-1. Evaluation Contractの凍結

Rubricを途中で緩める抜け道を防ぐため、作成前に目的、必須条件、配点、Hard Gateを確定します。要件変更時は連続合格をリセットします。

### 3-2. ブラインド採点

独立採点者は、最初の採点前に作成者の自己説明、過去得点、批判者のSeverityを見ない設計です。採点後に批判者の指摘と照合し、根拠があれば維持または減点します。

### 3-3. 同一成果物の連続2回合格

PASS 1後に成果物を凍結し、PASS 2は同じ内容を失敗中心・境界条件中心で再評価します。間に1文字でも変更した場合は連続回数を0へ戻します。

### 3-4. 得点上限制

- Critical残存：最大79点
- High残存：最大94点
- 必須条件未達、重大誤り、必須検証失敗、重大回帰：95点以上禁止

### 3-5. 本当の独立性に関する注意

単一モデル・単一会話だけでは、完全な統計的独立性は保証できません。そのため、別エージェントや別セッションが使える場合は実分離を優先し、使えない場合だけ模擬ブラインド・ハンドオフとして動作し、その事実を最終報告へ明示する設計です。

## 4. 主な失敗パターンと対策

| 失敗 | 対策 |
|---|---|
| 目標点へ合わせて採点を上げる | 途中の配点変更禁止、得点根拠必須、上限制 |
| 作成者の説明に採点者が引っ張られる | ブラインド入力、自己説明を採点者へ渡さない |
| 1回だけ偶然95点になる | 同一成果物の連続2回合格 |
| PASS 1後の修正を同じ連続扱いにする | 内容変更時は連続回数を0へ戻す |
| 5件を作るため問題を捏造する | 重大問題が少ない場合は相対的弱点として正直に表示 |
| 無限改善で終わらない | Hard blocker時は未達報告と再開パッケージ |
| 修正で別の問題が生じる | 毎ROUNDの回帰チェック |

## 5. 単一実行内の品質レビュー

以下は別モデルによる独立評価ではなく、同一実行内で役割を分けた検査結果です。

| 検査 | 得点 | 判定 | 主な確認 |
|---|---:|---|---|
| PASS 1・要件中心 | 98 / 100 | PASS | 4役分離、上限制、採点操作禁止、連続2回条件を確認 |
| PASS 2・失敗中心 | 97 / 100 | PASS | 同一成果物凍結、リセット条件、到達不能処理、回帰を確認 |

残る相対的弱点は、長文で実行負荷が高いこと、別エージェント非対応環境では独立性が模擬になることです。これらは隠さず主成果物へ明記しています。
