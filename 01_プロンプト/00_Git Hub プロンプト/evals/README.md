# プロンプトの評価

15件はテスト設計であり、生成性能の実行済み証拠ではありません。
実際の失敗例を優先し、不足だけを合成ケースで補っています。各JSONにoriginを記録しています。

## まず評価用フォルダを作る

```bash
python scripts/run_evals.py --prepare --run-id trial-001
```

`evals/runs/trial-001/` にrun.jsonとtasks.jsonlが作られます。初期結果は全てNOT_RUN。
同じ入力を旧版と改善版へ渡し、モデル・環境・設定・実行日時・出力ファイルを記録してください。
このスクリプトはAPIを呼び出しません。チャット、Codex、社内の承認済み評価基盤での実行を想定しています。
課金APIや機密データの外部送信は、利用者が許可した範囲に限ります。

## 結果を記録する

run.jsonのmodel、environmentを実際の値にし、各ケースのexecution、result、evidence_file、notesを記録します。
証拠ファイルはそのrunフォルダ内の相対パス。実出力とツールログを保存し、シークレットは含めません。
モデルではなくPythonで検査器を試した場合、notesにその対象を明示します。モデル出力の評価にすり替えないでください。

```bash
python scripts/run_evals.py --check-results evals/runs/trial-001/run.json
```

未実施の必須ケースは終了コード2、失敗は1、要求範囲の必須成功は0。
ファイルの存在チェックは実験の真正性の証明ではありません。人間または監査担当が実出力と環境を照合します。
自己評価はSIMULATED。同じ会話の役割変更を独立モデル実行と呼びません。

## 比較

評価基準は出力を見る前に固定します。候補名を伏せたペア比較を使い、重要な条件では繰返し実行します。
開発に使ったケースはdevelopment集合。未使用holdoutは別に追加します。今回の15件を未使用holdoutとは呼びません。
構造点数が高くても、MUST違反や重要な未実施がある場合は採用しません。

## 今回のパッケージ

unittestで検証器・ビルド処理の正常／負例を実行しています。15件すべてを実モデルへ投入したわけではありません。
実行済み／机上確認／未実施の内訳はreportsとVALIDATION_REPORTに分離して記録しています。
