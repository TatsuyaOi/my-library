## 今回の設計判断（INFERENCE）

プロンプトの本文を大幅に短縮するより、既存の用途別ルールを保持した最小差分と、共通の実行契約・管理スクリプトを組み合わせました。
`プロンプト一覧/` を正規パスとし、Component Versionは冒頭、Suite Versionは設定に分離します。ファイル名へ版を繰り返し埋め込みません。
CIはManifestを読み取り検査だけし、修復は変更ブランチで明示的に行います。モデル評価用の外部APIは自動では呼びません。
Library公開は既定で無効にし、対象buildに結びついた監査証拠と公開許可が揃った場合のみ進めます。

## 採用しなかったもの

「自己採点が90点以上なら自動merge」「毎回00〜09を全部実行」「CIでManifestを修復してから合格」「全資料フォルダを公開先へ丸ごとコピー」は採用しません。
特定のLLM評価APIや最新モデル名への固定も避けました。接続・費用承認がないため、自動的な有料モデル比較は実装せず、プロバイダー非依存の実行記録方式にしています。
これらは人気や点数を品質の根拠にする設計ではなく、対象の証拠と変更範囲を追えるようにするための選択です。
