# 既存プロジェクトへの移行

## 前提

このパッケージは既存リポジトリを直接変更していません。既存構成と秘密情報の有無は未確認です。
同名のAGENTS、config、scripts、Workflowがある場合、全上書きせず差分を比較します。

## 安全な導入順

1. 現在のGit statusを確認し、未commit変更を把握する。作業ブランチを用意する。
2. ZIPの内容を作業用ディレクトリで開き、以下の対応表で現行プロンプトを照合する。
3. 正規フォルダ「プロンプト一覧」に現行ファイルを1本ずつ配置する。
4. 旧版はGit履歴または明示したアーカイブで保持し、現行フォルダからの削除は確認済みの対応に限る。
5. AGENTS、設定、スクリプト、Issue/PR、CIは既存内容を保持して統合する。
6. CHANGELOG更新→Manifest同期→検証→PR差分確認。
7. Pages/本番の設定変更は別の明示した作業として実施する。

## 改行とハッシュ

今回の元添付では、03以外の多くがCRLF、旧ManifestはLF時のhashでした。LFに正規化すると、03以外の登録済み内容は旧Manifestと一致しました。
改行はbyte単位のhashに影響します。今回の新規セットはUTF-8・LFです。
既存content正本まで一括改行変換しないでください。変換を行う場合は別の変更として記録し、guide/preview/metaの生成元証拠を見直します。

## 日本語フォルダ

パスは引用して扱い、スクリプトはUTF-8を前提にします。正規IDは英数字kebab-caseのままです。
機械処理から日本語名を避けるためだけに、ユーザーが指定したフォルダ名を勝手に戻しません。

## 既存サイトを壊さない

同梱のLibrary用設定は導入例です。既存カテゴリ・公開パス・テンプレート・PWAは既存設定を優先して統合してください。
`site/` は生成物だけの管理ディレクトリです。既存の手編集siteを初期化しないでください。
本番のindex/PWA一式は今回の入力ではないため、同梱ツールのテスト成功を既存サイト検証の代わりにはしません。
